## 구현을 위한 선택지와 진입 게이트
1. **우선 진행 경로: 독립 웹 게임용 PG**. 토스페이먼츠 결제창/위젯 + 별도 인증/원장 HTTPS 서버를 **우선 검토 후보**로 삼는다. 포트원 V2는 PG 통합 대안이며 확정 계약/가격에 따라 결정. 두 공급자 모두 현재 연결하지 않았음.
2. 이후 Play 배포 버전은 Google Play Billing 별도 adapter로 검증해야 한다. 한국 지역의 게임 대체 결제는 별도 Play 정책 등록·거래 보고 및 고객 선택 UX 요구를 확인해야 하며 임의로 웹 PG만 심어 우회 금지.
3. 구매 전 계정 복구 가능한 OIDC 인증 공급자/PG 상점ID/사업자/서비스 운영 주체/서버 및 DB/비밀키 관리·실제 SKU별 가격과 콘텐츠를 확정해야 한다. 제공자 견적이나 운영 정책 미확정 → 실비용 추정 확정 금지.
4. M03 `spendBucket`은 내부 소비(debit) 전용. **새 유료 결정 지급(credit) API 없음**, 웹 PG 트랜잭션 검증/취소/정산 서버 기능 없음. M04에서 원자적 크레딧 작업을 구현·검증해야 한다.
5. Toss의 기본 결제 상태 웹훅에는 보편적 HMAC이 있다는 가정을 버리고 서버 `paymentKey/orderId`로 결제 조회/금액 확인. 이벤트 종류별 웹훅 진위 절차가 다름. 포트원 V2는 서버 단건 결제 조회와 `PAID`·금액 검증; 실제 계약 버전/채널 스펙은 40% 구현 전에 재확인.
6. 가격은 반드시 **검증된 제공자 카탈로그/실 주문**과 일치해야 하며 M01의 null 가격, M02 시뮬레이션 가격으로 실제 구매 시작 금지.
7. 게임에 없는 외형/시즌 패스를 미리 판매하지 말 것. 독립 획득 원천, 구매 복원/사용자 지원, 취소·환불 정책 선확정.

**40%**: M04 공급자 중립 **모의 adapter**/서버 검증 계약/내부 주문 영속 구조 프로토타입, 취소·중복 알림·클라이언트 변조 응답 503 차단. 실제 PG 호출 및 비밀키 개설은 운영 계정 자격증명과 연결 허가가 갖춰질 때까진 수행하지 않음.

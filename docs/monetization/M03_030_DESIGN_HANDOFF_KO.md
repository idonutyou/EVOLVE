## 안전한 기본 설계
1. 실제 계정은 신원 제공자에서 검증된 사용자 식별자를 서버가 매핑한다. 익명 브라우저 값이나 localStorage를 유료 자산의 증명으로 취급하지 않는다.
2. `EVOLVE_V575_TEST_*` 오프라인 게임 저장과 무료 DNA를 손대지 않고, 별도 서버 `mutation_crystal` 무료/유료 출처 버킷만 관리한다.
3. 거래는 인증→계정 소유권→idempotency + request fingerprint→계정/지갑 고정 순서 잠금→잔고 검증→immutable 원장/권리 출처 기록→단일 COMMIT. 무결성 실패는 전체 롤백. wallet snapshot은 원장 집계로 재대조.
4. 독립한 외형 구매 원천이 두 개면 환불된 원천만 무효화하고 다른 유효한 원천을 유지한다. 사용된 재화의 환불은 음수 잔고/자동 권리 박탈 대신 수동 검토 상태에 둔다.
5. 클라이언트 성공 URL, SKU 가격·지급량 입력, 모의 PG 이벤트/영수증 문자열, 서버 미검증 임무 결과로 지급 금지. 모든 checkout/provider/reward API는 실제 연결 전 `503`/비활성.
6. 장기 bearer token/서비스 role 키/DB 연결 정보/PG 비밀키를 GitHub Pages, public repo, 클라이언트 JS에 저장하지 않는다. 짧은 수명 인증 토큰, 로그인 복원/세션 취소, 허용 출처 CORS·CSRF 정책 필요.
7. 공급사/리전/운영 비용은 미확정. 설계 선호는 HTTPS Node 계열 API + 트랜잭션 PostgreSQL. 실제 공급사 요금, 정산·개인정보 관련 정책은 최신 근거와 운영 주체 확인 뒤 결정한다.
8. DB 백업의 복구 시연, 접근 권한 최소화, 로그 보존/삭제, 비용 상한 및 장애 경보 필수. RPO/RTO 등 SLA는 아직 확정하지 않는다.

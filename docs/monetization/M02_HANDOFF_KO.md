# EVOLVE — M02 무료·유료 재화와 과금 상품 경제 인수인계
작성: 2026-10-27 KST | 시작 대기 | M01 100% 전략/QA 계약 완료 후 다음 단계

## 최우선 이유
**돈을 쓸 구체적인 이유와 합리적인 수량/가격을 먼저 정한 뒤** 구매 서버(M03)와 첫 실제 결제(M04)를 연결한다. 상품 목록만 만들고 구매 가치가 없는 상점은 EVOLVE의 최우선 수익화 요구를 충족하지 못한다.

## 고정된 상속 조건
- 공개 게임은 V614, 기존 이미지·능력치·게임 레벨/카드 확률·세이브 유지.
- `monetization/catalog/draft_skus.json`: 계정 1회 스타터팩, 유료 재화 소/중형, 확정 코스메틱, 시즌패스 후보 **5종**. 전부 `draft_disabled`; 가격·지급량 `null`.
- 기존 브라우저 DNA는 **무료 재화**, 유료 `mutation_crystal`과 직접 교환/동일시 금지. 프리미엄 화폐 서버 원장 필요.
- M01 테스트 51/51 통과는 실제 결제, 앱심사, 광고/운영수익이 성립했다는 뜻이 아니다.
- 신규 이미지 렌더링은 M02 단계에 **불필요**. 기존 테마 재활용 가능한 확정형 상품부터 설계하고 새로운 스킨 일러스트가 필수이면 미리 통보.

## M02 / 1-of-3 (10–30%) — 먼저 실제 수치 조사
**10%:** V614 소스에서 DNA 획득 지점(전투/맵/클리어/보스), DNA 소모 지점(상점/연구/성장), 1판 보상/스테이지별 기준과 `localStorage` 저장·초기화·복귀 동작 확인. 실제 코드로 찾지 못한 소비처를 없는 것처럼 만들거나 임의로 가격을 확정하지 않는다.
**20%:** 최소 3종의 무료 성장 페르소나/시간 시나리오(무과금 20분/일, 무과금 60분/일, 소액 구매)와 실제 획득/소모식 계산표. 경제 루프: 입장 → 전투 3~5분 → 보상 → 연구/외형 소비 → 다음 전투. 프리미엄 실지급·재구매·승률 비교. 기존 S23+ 장시간 렉 미해결임을 별도 표시.
**30%:** 각 SKU별 제공량과 KRW 가격의 **시험 시나리오** (VAT/판매수수료/환불/판매자 조건을 반영), 첫 구매 가치/반복 구매 동기/무료 성장 시간 대비 편의, 확정형 소비처. 가격표/보상 수치는 후보로 표시, 오인 가격·허위 할인 금지.

## M02 / 2-of-3 (40–70%) — 구현 및 검증
**40%:** 재화 획득/소모 시뮬레이터, source-of-truth 경제 설정 JSON과 최소 단위 테스트. 서버 API/실결제 비활성 유지.
**50%:** 구매 단가/패키지 제공량·무료 적립 보상 속도의 보수/중립/공격적 시나리오 비교. 결제자에게만 접근 가능한 필수 능력치 금지, 핵심 진화·TITAN 완주 가능.
**60%:** 일/주 소모·잔고, 첫 구매 전환을 유도할 가치 제안, 코스메틱/패스 등 비소모 재방문 동기, 과금 없이 3·7일 성장이 정체되지 않는지 검증.
**70%:** 순매출과 수수료/부가세/환불 계산의 민감도 및 경제 악용(로컬 DNA 위조가 유료 결정으로 연결되는지) 검증. 기존 무료 보상·스킬 수치 바꾸는 패치는 분리 검증.

## M02 / 3-of-3 (80–100%) — 확정 경제 사양
**80%:** 제공할 상품 소비처와 무료/유료 대체 루트 동선·재화 상한/잔고/권리 정책 확정.
**90%:** 서버 상품 카탈로그에 넘길 priceId/sku/quantity/entitlement catalog 계약을 별도 파일로 정리. 승인된 상점 가격표/결제 계정이 없으면 여전히 구매 disabled.
**100%:** 최종 분석/백업/보안/무료 플레이 공정성 점검 후 M03 계정·실영수증 권한 원장으로 인수인계.

## 필수 경제 분석 항목
- 플레이당 기대 무료 DNA = 적 처치/스테이지·보스/클리어/첫 완료 보상 - 중복 보상; 현재 게임에서 실제 발생하는 event 기준만 추출.
- 연구·성장 소비처를 실제 UI/소스에서 분류: 반복/영구/소모형·해금형·완료형, 구매 시 재화가 감소하는지 QA 확인.
- 구매 동기: 성장 시간을 **덜 기다리는 편의**, 게임 컨셉에 맞는 진화 외형/연구 테마, 한정 시즌 도감 수집. 성능 우위를 절대 구매자로만 독점시키지 않는다.
- 결제 실금액은 상품 설명·서버 검증·결제업체 지역 가격과 일치해야 한다. 샌드박스 코드에 하드코딩한 모의 10/20/50 결정 수를 실제 지급량으로 오인하지 않는다.
- 광고는 M06 승인 전 '시청했다' 사용자 입력으로 서버 프리미엄 적립 불가; M02의 광고 기대수익은 사업자 승인 뒤 보수적으로 반영.
- 전환·유지·순매출/ARPPU·ARPDAU 예측은 모델 가정으로 표기. 실제 사용자 데이터/실결제 없이는 확정 수익 예측 금지.

## 인수인계 차단 조건
- M02 보고서만으로 유료 결제를 켜지 않는다.
- M03 로그인·영구 DB/원자적 원장·권리 복원, M04 판매자 계약/실거래 영수증 검증이 마련될 때까지 `DRAFT_ONLY` 상품 유지.
- 10%마다 전체 Git snapshot remote backup, 단계를 1/3·2/3·3/3으로 나누어 진행.

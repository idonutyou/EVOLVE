## 목적
M01의 구매 후보 5개를 실제 판매하기 위해 판매 채널/운영사 선택 → 제공자 샌드박스 → 서버 검증 → 중복/환불/권리 처리 → 실제 가격·고객지원·출시 심사를 단계적으로 통과해야 한다. GitHub Pages는 정적 클라이언트이므로 **브라우저를 신뢰하지 않는 별도 HTTPS 서버**가 반드시 필요하다.

## M03에서 인계받을 실제 리소스
- `m03-server/`: 개발 전용 API 및 PostgreSQL 엔트리·지갑·기술 스키마/회귀 검사. `NODE_ENV=development` + 별도 실행 플래그 없이는 구동 차단, 서비스용 시크릿 없음.
- `docs/monetization/M03_100_FINAL_REPORT_KO.md`: 검증 범위/미구현.
- `monetization/catalog/draft_skus.json`: 5 SKU `draft_disabled`, 현재 가격·권리·수량 null. 실제 제공자 카탈로그 검증 전 UI에 M02 가상 가격 표시 금지.
- `monetization/contracts/payment_api_contract.openapi.json`: M01 가상 API 계약; 클라이언트 결제 성공 URL은 결코 지급 근거가 아님.
- CI 실DB 증거: https://github.com/idonutyou/EVOLVE/actions/runs/40508368361 , 22/22; 운영 계정/PG 검증과는 별개.

## 사전에 결정·확인할 사항 (비용/계정 연결 전)
- 우선 출시 채널: 현재 정적 **웹** 그대로 결제할지, 추후 Google Play/앱 마켓 빌드를 출시할지. 각 채널별 인앱 결제/정책이 달라 채널 선정부터 조사.
- 사업자·가맹점 계정/서비스 운영 주체, 한국 등 서비스 지역·통화, 세금/환불·미성년자 판매 조건과 계정 복구 정책.
- 운영 인증 제공자와 토큰 키 회전/JWKS·세션 폐기 및 유저 계정 연결/탈퇴. 실제 운영 DB 권한·RLS, 비밀키 저장·로그/백업 정책.
- 유료/무료 mutation_crystal 사용 우선 순서, 환불·차지백 후 잔여/이미 사용한 결정 처리, 외형 권리 복원/취소 근거.
- 실제 가격·수량/코스메틱 상품 콘텐츠 준비 전 **판매 유도 UI·결제 활성화 금지**.

## M04 단계/검증 게이트
**STEP 1/3 (10~30%)**: 서비스 채널·PG 및 정책 비교, 결제 제공자 API/테스트 자격증명 정책, 주문·상품/가격 서버 검증·환불 상태 기계·방어적 계약 문서화, 계정·비밀키/개인정보 운영 설계. 결제사 서비스 연결·비용 발생 전 사용자 운영 계정 필요 여부 확인.

**STEP 2/3 (40~70%)**: 별도 개발용 provider adapter/샌드박스 서버, 서명+timestamp/replay+provider transaction/order/account/price 검증, 서버 트랜잭션 원자적 credit/reverse, 중복 청구·취소·전달 지연 테스트. 브라우저 return URL 단독 지급 금지. 검증된 상품과 스테이지 게이트 없이 라이브 플래그 true 금지.

**STEP 3/3 (80~100%)**: PG 제공자의 실제 샌드박스 증빙, 주문 상태 불일치·환불·부분 실패 복구, DB/로그 권한과 개인정보/비밀키 관리, 운영 비용·품질·고객지원·실판매 준비 게이트. 서비스 출시/실거래 활성화는 모든 선결 조건 충족 후 별도 승인.

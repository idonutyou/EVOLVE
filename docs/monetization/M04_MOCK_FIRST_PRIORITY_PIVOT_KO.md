# EVOLVE — 수익화 우선순위 교정 / 모의 구매 우선 실행 규칙

확정일: 2026-10-27 KST
사용자 지정 최상위 목표: **최종 출시는 Google Play 및 Apple App Store. 웹은 개발/테스트 전용.**
**지금 필요한 것은 진짜 결제사 연동이 아니라, 게임 내 과금 상품·가치·구매 경험·획득 효과를 완성하고 모의 결제로 플레이 검증하는 것.**

## 전환 결정 (이전 결제 인프라 우선 계획 대체)
1. **과금 요소가 먼저**: 진화 외형, 신체 부위/코어 테마, 무기 외형·이펙트, 스타터 상품, 결정 상품, 시즌 수집·패스 등 실제 사용 가능한 게임 콘텐츠를 먼저 만든다. 실제 구매 보상으로 기능하는지, 사기 전/후의 플레이 가치가 있는지 테스트한다.
2. **구매는 모의로**: 개발 중 상점에서 가짜 결제 완료를 누르면 무료 테스트용 상태에만 상품을 지급한다. 재화·소유권·장착·재구매 제한·환불(테스트 초기화)/복구 UI 시뮬레이션까지 구현한다. 실제 카드 결제/PG/사업자·상용 인증 서비스는 연결하지 않는다.
3. **모의 구매와 실제 자산 엄격 분리**: 테스트 구매 기록은 `MOCK_ONLY` 네임스페이스와 `mock_transaction_id`, `source=dev_mock`으로 격리. M03 서버 유료 원장·라이브 계정 권리, 운영 구매 증빙·환불로 절대 승격/전환하지 않는다. 개발용 저장/마이그레이션 정책 별도; 기존 `EVOLVE_V575_TEST_*` 저장 키와 무료 DNA는 변형·삭제하지 않는다.
4. **스토어 결제는 나중에 연결**: 실제 완성·상품 ID·수량/가격·권리 정의 확정 후 Android = Google Play Billing, iOS = Apple StoreKit 2 연동. 플랫폼별 결제 검증·구매 복원·취소·환불/차지백과 M03 서버 원장을 연결한다. 실제 연동은 최종 단계이지만 **상품 ID, 권리 인터페이스, 중복 지급 안전 설계는 지금부터 고정**해 나중에 전체 상점 재작성 방지.
5. **웹 결제사(토스/포트원) 우선 작업 중단**. 기존 조사 문서는 '과거 참고용'으로 보존만. GitHub Pages는 개발·테스트 전용이며 웹 결제를 출시 채널로 보지 않는다.
6. **라이브 판매 비활성 유지**: `monetization/catalog/draft_skus.json`의 5개 SKU, `checkout_enabled=false`, 결제 수수료/PG/비밀키·서비스 가입 상태 그대로. 데모 가격 표기는 반드시 '시뮬레이션, 실제 판매 가격 미정'으로 표시.
7. **유료 가치 목표**: 재미를 박탈하지 않는 편의/수집/외형/특별 연출 우선, 전투 밸런스/유료 반복 소비는 게임성 검증 후 결정. 유료 전용 필수 진행 차단은 두지 않는다.

| **M05: 상점·인벤토리·구매 UX** | 상점 입장, 패키지·결정·외형·시즌 탭, 상품 설명/미리보기, 구매 모의 팝업, 소유/장착/잔고 표시 | 휴대폰 화면에서 작동하는 완성도 높은 사용성, 테스트용임을 명확히 표시. |

| **M07: 반복 가치·장기 동기·경제 밸런스** | 시즌/패스·패키지·미션·보상 순환, 이탈/진입 장벽·무료 경험·가치 검증, 선택형 광고 보상은 모의 상태로 보존 | 모의 결제로 유저 행동 검증, 조작 가능한 수치와 수집 동선 확정. |

## M04 다음 작업 — 중단된 설계부터 반복하지 않음
- 이전 M04 STEP 1/3 (10~30%)의 결제사·주문 검증 자료는 아카이브. **M04 30% 설계 체크포인트를 사용자의 이 결정으로 교정**한 뒤, 다음 `고`에 **M04 STEP 2/3 40%: 모의 결제/상품 획득 시스템의 실제 게임 연계 개발** 착수.
- 40% 진입에서 먼저 기존 EVOLVE 게임 구조(인벤토리·스킨·결정·상점·저장 경계)를 확인하고, 신규 테스트 전용 저장 키/상점 플래그를 생성한다. 기존 게임 파일 보전/백업 이후에만 실제 코드 수정.
- 50%: 모의 구매 지급/사용/장착/소유권 재구매/거절을 단일 게임 API로 연결.
- 60%: 패키지/결정·외형·시즌 상품의 실작동 가치, 장착/해제 및 저장/재시작 테스트.
- 70%: 모의 환불·구매 복원·저장 안전성/모바일 UI 회귀; 적절한 사용자 확인 후 게임 배포.
- 후속 80~100%: 회귀·상용 결제 분리/완성도 품질 확인·M05 인수인계.
- **이미지 렌더링**: 현재 이 방향 교정과 모의 결제 엔진 설계/초기 구현에는 불필요. 새 스킨/외형 실제 아트 제작 STEP 시작 전에 필요 여부를 미리 알림.

## 지켜야 할 기존 규칙
- 매 단계 3 STEP, 10% 단위 원격 브랜치 백업 후 독립적 2회 검사, 기존 백업 삭제 금지.
- public `dist/`와 작업 브랜치 분리, 기존 확정 맵·스킬·보스·이미지·저장키 침범 금지.
- '모의 결제 완료'를 '실제 결제 완료'라고 홍보하거나 실제 구매 증빙으로 취급하지 않는다.

## 1. 왜 상품 상세 화면이 먼저인가?

M04 상점은 개발 테스트용 목록과 버튼을 제공한다. M05는 상품마다 **무엇을 얻는지 / 어떤 재화를 사용하는지 / 실제 돈을 쓰는지 / 이미 보유했는지**를 혼동 없이 설명해야 한다. 구매를 유도하는 화면에서 허위 할인·한정 판매·가짜 가격을 만들지 않으며, 실제 결제 기능이 없다는 사실을 제목과 확인 창에 모두 표시한다.

상품 상세는 `상품명 → 기존 원본 캐릭터/코어 발광 미리보기 → 실제 TEST 지급물 → 소유/결정 잔고 → 이용 가능 이유 → 명시적 확인 → 개발 전용 고지` 순서. 페이지에서 정보를 읽거나 미리보기를 여는 행위만으로 영수증을 생성하지 않는다. 상세 화면에서 뒤로 가도 상품 목록 스크롤과 선택 SKU는 유지한다.

## 3. 코어 컬렉션 상태

- **공명 코어:** 모의 상품을 지급받지 않았으면 ‘상품에서 모의 획득’, 소유하면 ‘장착’, 장착 중이면 ‘해제’.
- **심홍 코어:** 미보유·TEST 결정 120개 미만이면 ‘결정 부족’, 120개 이상이면 ‘120개로 해금’ → 취소/확인. 소유 후에만 ‘장착’ 또는 ‘해제’.
- 캐릭터 원본과 M04에서 캐시한 발광 레이어만 미리보기. 새로운 캐릭터 그림이나 유료 아이템을 생성했다고 주장하지 않는다.
- 소유/장착 정보는 `EVOLVE_DEV_MOCK_STORE_V1`에서만 읽고/쓰며 `ORGANISM`의 실제 게임 파츠, DNA, 전투 능력치 저장과 절대 병합하지 않는다.

## 4. 동작 우선순위 (높음 → 낮음)

1. 허용된 개발 호스트와 `?evolveMockShop=1`가 아니면 상점 기능 자체를 숨김.
2. 홈 밖(전투 중), 손상되거나 읽을 수 없는 테스트 저장, 현재 처리 중, 확인창 대기 상태에서는 중복 구매 차단.
3. 시즌 상품은 준비 중 / 이미 받은 일회성 패키지는 보유 중.
4. 기존 코어 소유 + 장착 여부에 따라 장착/해제.
5. 심홍 코어 미소유 + TEST 결정 부족/충분 여부에 따라 비활성/해금 확인.
6. 반복 가능한 결정 묶음은 매번 새로운 **명시적 확인**을 받은 경우에만 테스트 지급.

## 5. 확인/취소·오류 UX

상태 순서는 `IDLE → DETAIL_OPEN → CONFIRM_PENDING → PROCESSING → SUCCESS/FAILURE`. 취소는 `CANCELLED → DETAIL_OPEN`으로 되돌리며 **localStorage 바이트 불변**. ‘120개 해금’은 확인창에 차감 전/후 TEST 결정 잔고를 명시한다. 확인 버튼 외부 터치·Esc는 취소 또는 아무 일도 하지 않도록 설계한다.

처리 중 닫기/재중복 확인으로 같은 항목을 중복 지급하지 않는다. 실패 후 재시도도 **기존 요청 ID**를 사용해 지급과 차감을 멱등 처리한다.

| 문제 | 보여줄 안내와 행동 |
|---|---|
| TEST 결정 부족 | 필요한 120개와 현재 잔고 확인, 해금 버튼 비활성 |
| 이미 소유 | 추가 지급 없이 컬렉션의 장착 동작 유도 |
| 기록 저장 실패 | 구매 실패 및 지급 없음 명시, 저장 영역 확인 유도 |
| 손상된 테스트 저장 | 구매·장착 차단, **자동 초기화/덮어쓰기 금지** |
| 시즌 상품 미완성 | ‘준비 중’, 확인창·영수증 생성 금지 |
| 요청 번호 충돌 | 영수증 추가 지급 금지, 명시적 오류 |
| 영수증 한도 도달 | TEST 기록 한도 안내, 게임 저장 그대로 |
| 빈 코어 컬렉션 | 상품 획득 경로 제공, 사용 가능한 외형이 없음을 명시 |
| 기록 없음 | ‘아직 테스트 구매 기록이 없어’, 환불되는 실결제처럼 설명 금지 |

완성된 각 오류 문구는 JSON의 `error_copy`에 실제 오류 코드(13개)를 키로 정리했다.

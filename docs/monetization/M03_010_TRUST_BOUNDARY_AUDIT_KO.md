## 데이터 신뢰 경계
1. GitHub Pages 웹 게임은 **신뢰할 수 없는 공개 클라이언트**. 클라이언트 제공 결제 성공 URL, 저장 DNA, 잔고, 이벤트 JSON, 브라우저 시각은 유료 크레딧 근거가 아니다.
2. 계정은 서버 발급 식별자와 서버 검증 세션으로만 식별. 구매/잔고/권리 데이터에 클라이언트 발행 `account_id` 소유 주장 금지.
3. 서버가 아닌 클라이언트는 DB 연결 권한·서비스 역할 키·PG 비밀키를 소유하지 않는다. DB는 외부에 직접 쓰기 가능한 공개 권한을 부여하지 않는다.
4. 계정·원장 데이터와 브라우저 오프라인 게임 메타는 분리한다. 기존 키 변경/수정·무단 마이그레이션 금지.
5. 포인트 출처: 게임 DNA(기존 브라우저 무료) / 서버가 검증한 임무 무료 결정 / 서버가 검증한 결제 결정. 서로 무단 교환 금지.
6. 주문·환불·권리·결정은 idempotency(반복 요청), 원자성, 사용자 소유 검증, 재시도·동시성 제어를 요구한다. 임의 유료 잔고 지정 API 금지.
7. M03 구현 전에는 **모든 지급·결제·광고 보상 경로 disabled-by-default**. 개발용 API는 프로덕션에서 차단하고 내부 테스트에서만 시험.

## 기술 방향(확정 배포 벤더 아님)
- 설계 기본: HTTPS JSON API + 서버에서 검증하는 인증 + 트랜잭션을 지원하는 PostgreSQL 계열 영속 저장소(구체 벤더·요금·권한·리전은 미확정).
- 공개 `dist/`는 정적 호스팅으로 보존; 서버는 별도 프로젝트·별도 시크릿 관리 및 환경 분리. 개발/시험 서비스도 테스트 아닌 실결제 허용 금지.
- 처음에는 게스트 계정의 결제 진입을 금지하고, 계정 복구 가능한 인증과 게임 데이터 처리·연동 정책을 검토한다. 계정 간 병합/양도는 자동 처리 금지.
- DB 백업은 스냅샷 + 복구 리허설 + 접근 감사로 운영하고, 환경별 키와 DB 사용료/무료 한도를 문서화한 후 리소스 생성.
- 기능 토글/PG 정책/실상품 정보는 서버 관리형; 이전 M01 카탈로그 값을 우회해 브라우저에서 승인하지 않는다.

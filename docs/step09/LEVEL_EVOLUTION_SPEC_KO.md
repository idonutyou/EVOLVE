# EVOLVE STEP 09 — 20% 레벨·카드·진화 슬롯 호환 설계
2026-10-27 KST | 문서 설계 전용 | V614 원본 능력치/카드 이미지/저장 **변경 없음**

## 1. 세 종류의 수치를 분리한다

| 모델 | 기존 기준 | STEP09에서의 목표 | 게임 플레이 변경 |
| --- | --- | --- | --- |
| `combatLevel` (기존 `state[organ]`) | 팔=1 시작, shell/tail/mouth=0 시작, 습득 후 1~5. 공격체계가 그대로 읽음 | **기존 한계 5와 기존 공격 계산 보존** | 없음 |
| `combatBonuses` (V593 + V598 stats) | 카드별 스탯 합산, 캡 및 발사/관통/각도 등 별개 | 증가량·희귀도·최댓값 바이트 기준 보존, `+0` 카드 제외 | 없음 |
| `evolutionProgress` (새로운 독립 누적 기록; 제안) | 없음 | 부위별 습득/전투 강화 선택 횟수로 달성한 **마일스톤 Lv.3 / Lv.6** | STEP09은 데이터/판정 인프라만. 실제 분기·공격 변경은 STEP10~13 |

**중요:** 현재 `state.shell`, `state.tail`, `state.mouth`의 게임 상한 5를 갑자기 6으로 변경하지 않는다. **Lv.6은 기존 능력치 레벨 6이 아니라 새 진화 진행 단계 6**으로 구현하자는 호환 설계다. 이름이 같아 혼란을 줄 수 있으므로 UI에는 `진화 Lv.3 / Lv.6` 또는 `변이 단계`로 명시, 기존 `공격 Lv.`와 구분. 명시적 사용자 승인 없이 실제 무기 계수나 레벨 UI를 바꾸지 않는다.

### 진화 진행 단계 계산 (미구현 제안)
- 시작: `arm`은 `evolutionProgress=1`, 다른 세 부위는 `0`. 현재 장착 총·칼·맨손을 교체하면 현재 팔 `weaponMode`에 맞는 보유 공격은 유지하되 다른 무기 전용 진화를 적용하지 않는다.
- `shell_learn`/`tail_learn`/`mouth_learn`을 **정상 카드 선택으로 습득**할 때 해당 부위 0→1. 같은 부위 학습 2회 방지.
- 진화 대상 부위의 **실제 공격 성장 카드**를 택했을 때 `growthSelections`가 +1, `evolutionProgress=Math.min(6,1+growthSelections)`. 예: 스파이크 습득 후 강화 2번이면 Lv.3, 강화 5번이면 Lv.6.
- 팔은 현재 모드의 `gun_*`/`blade_*`/`bare_*` 강화 카드를 **정상 선택**했을 때 성장 +1. ARM 시작 Lv.1; 2회 더 선택하면 Lv.3, 5회면 Lv.6. 그러나 기존 전투용 `state.arm`은 1에 머무르게 하여 총알 수/검베기 세기 등 기존 계산이 중복 증가하지 않도록 한다.
- `health`, `giant`, `armor`, `regen`, `move`, `light` 같은 **수동 생존 카드**는 진화 진행을 올리지 않는다. `shell` family로 분류되더라도 `c.organ`가 아니므로 성장 계수에서 제외한다.
- 특정 `organStat` 카드가 캡에 걸려 제공 풀에서 사라져도 **다른 사용 가능한 공격 성장 카드**를 선택해 진화할 수 있어야 한다. UI/공격 스탯을 caps 이상으로 확장하지 않는다.
- rarity는 획득 카드의 능력치 증가량에만 적용한다. **신화 카드 1장이 진화 마일스톤 5단계로 뛰는 일 없음**. 반복 선택 1회=성장 기록 1개.
- `Lv3` 선택지 상태 제안: `locked → eligible → presented → chosen` (Lv3 도달, 선택된 분기 스냅샷, 되돌리기 여부는 향후 정책). `Lv6`은 `progress≥6 && Lv3 branch chosen`에서만 eligible. **미선택 진화를 랜덤으로 자동 적용하지 않는다**. 인게임 3장 카드를 0~2장으로 줄이거나 필수 선택을 강제하지 않는다.
- STEP09 2/3에서는 진화 **메타데이터/순수 선택자와 회귀 테스트만 활성화**, 전투 효과 분기나 외형 변경은 OFF. 선택 UI/진화 카드 도입은 STEP10~12에서. 기존 세이브에는 진화 키를 쓰지 않고 런타임 시 선택 기록으로 재구성 가능한 구조를 사용.

## 2. 추첨 순서·빈도를 분리한다
1. **자격 필터**: `upgradePoolV593()`, 해당 런에 현재 장착한 `armItemModeV589()`만 허용. `_equip` 카드는 제외; 미습득 부위는 `_learn`만, 습득 후 스탯 카드만. `mouth`가 BREATH이면 count/pierce 제외. 각 카드의 고정 또는 동적 수치 상한 검사.
2. **부위 가족**: `organ||group`. 임의로 기본 확률 조작하지 않으며, 서로 다른 최대 3가족을 고른다. 개막 ARM을 **무조건 포함**, 남은 두 부위를 독립 가족에서 고른다. 가족 수가 셋보다 적으면 fallback으로 미장착 무기 카드를 삽입하지 않는다. 카드 부족/모든 부위 캡 상황은 별도 fallback 사양을 검토.
3. **가족 내 카드**: 그 가족의 합법적인 카드 중 랜덤 1개. `shell`에서 Lv.0일 때 생존 패시브 카드와 `shell_learn`을 구별하고, 생존 패시브가 가시 습득·진화 성장으로 집계되지 않게 한다.
4. **등급**: 각 카드마다 커먼 0.60 / 레어 0.27 / 에픽 0.10 / 전설 0.027 / 신화 0.003을 **독립** 추첨; 전설/신화 카드는 초반에도 확률상 나타날 수 있다. **일반 카드의 rarity 확률과 특정 부위 카드가 등장할 확률을 혼동하면 안 됨**.
5. **클릭 적용**: 3장 중 1장만 확정; 선택 카운트 1 증가; 렌더 UI/반응 조건 `choiceInputReady`, 재롤 횟수 및 크기·이미지 크롭 동일. 재롤은 확정 선택이 아니므로 성장 이력·진화 진행·특정 부위 level을 증가시키지 않는다.

## 3. ARM/스킬/이미지 불변조건
- `mode=cannon` → gun만; `mode=blades` → blade만; `mode=bare` → bare만. **총 장착 시 칼, 칼 장착 시 총의 레벨업 카드가 보이면 P0**.
- 장착 ARM 자체는 Lv.1로 공격 가능; shell/tail/mouth 미습득은 Lv.0 완전 공격 금지.
- 몸체 외피(skin), 꼬리(tail), 입(head) 장착 파츠가 해당 공격 프로필을 결정하되 `skillVariantsV598`의 슬롯 일치 여부 검증. 기본 침은 물리 직선 spit; 독·화염·얼음은 장비 매핑이 실제로 있어야만 활성.
- STEP06 제외로 지시된 **침 타격감 작업**과 STEP09 **침 학습·카드 규칙**은 다른 사항이다. 침 기능/카드를 삭제하지 않는다.
- 기존 V610 가시·채찍 카드 이미지, 동일 비율·크롭 및 모션 감소, UI 표시 현재 레벨, 리롤/터치 영역 보존. 이미지 새 렌더링·기존 파일 덮어쓰기 없음.
- 레벨당 XP=12, 장기 레벨 제한 없음, 캐릭터/장비/스킬 저장 키 변경 금지.
- 전격은 기존 장착/잠금/자동 시전 규칙 그대로, 이번 신규 evolution 계수로 전격이 원치 않게 해금되지 않도록 함.

## 4. 진화 분기 데이터 계약 (모델 제안, 현행 게임 미구현)
```js
{
  organ: 'shell'|'tail'|'mouth'|'arm',
  weaponModeAtSelection: null|'cannon'|'blades'|'bare',
  earnedSelections: 0, // learn은 성장 카드 수로 세지 않음
  rank: 0|1|2|3|4|5|6,
  milestones: {
    three: { state: 'locked'|'eligible'|'presented'|'chosen', pathId: null|string },
    six: { state: 'locked'|'eligible'|'presented'|'chosen', pathId: null|string }
  }
}
```
- 진화 선택지는 **서로 다른 공격 형태**를 의미하며 `pathId`와 실제 효과 함수를 혼합하지 않는다. Lv.3 외피/꼬리 분기는 STEP10, 팔/입은 STEP11, Lv.6 심화 진화는 STEP12. STEP13은 실제 파츠 외형 레이어와 성능.
- STEP09 자체가 미래 분기·전용 그림을 **생성하거나 배포하는 단계가 아니다**.
- 원본 무기 성장 값과 새 진화 상태를 분리해 전후 비교에 실패하면 새로운 진화 기능을 공개하지 않는다.

## 5. 거부해야 할 변경
- `state.arm`을 기존 권한 없이 3 또는 6으로 덮어쓰는 변경.
- `Math.min(5,state[organ]+1)`을 의미 검증 없이 제거해 기존 타격·이미지 애니메이션을 깨는 변경.
- 희귀도 확률, 각 카드 count/mult, +10%/+12%/30° 등 모든 확정된 원래 카드 증가량 재밸런싱.
- 진화 도달 시 **자동 분기를 선택하거나** 현재 장착 무기를 강제로 바꾸는 구현.
- 새로운 에셋 렌더링을 알리지 않고 선행하는 작업.
- 등급 확률 60/27/10/2.7/0.3을 부위 가족 선택 확률로 오해하는 로직.
